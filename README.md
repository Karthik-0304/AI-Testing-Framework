# AI Testing Framework

An AI-powered testing framework that validates shipment information generated by a Large Language Model (LLM) against trusted API data. The project combines API testing, AI response evaluation, automated test execution, and HTML reporting using Python.

## Project Overview

This framework tests whether an AI assistant provides accurate shipment information, including shipment status and destination. It compares the AI-generated response against trusted data returned by a shipment API and reports whether the response meets the expected criteria.


## Key Features

- **REST API Testing:** Validate shipment endpoints, response fields, status codes, and invalid shipment IDs.
- **AI Response Evaluation:** Check AI-generated answers against trusted shipment information.
- **Gemini Integration:** Send prompts to Google's Gemini model and validate its responses.
- **Negative Testing:** Test incorrect statuses, destinations, unrelated responses, and conflicting information.
- **Automated Test Execution:** Run the test suite using pytest.
- **HTML Test Reports:** Generate a self-contained HTML report with individual test results.
- **Environment Configuration:** Load the Gemini API key from an environment file.

## Getting Started

### Prerequisites

- Python 3.11 or a compatible Python version
- pip
- A Google Gemini API key for live AI integration tests

### 1. Clone the Repository

```bash
git clone https://github.com/Karthik-0304/AI-Testing-Framework.git
cd AI-Testing-Framework
```

Replace the placeholder with your actual GitHub repository URL.

### 2. Create a Virtual Environment

**Windows PowerShell:**

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

### 3. Install Dependencies

```powershell
python -m pip install -r requirements.txt
```

### 4. Configure the Gemini API Key

Create a `.env` file in the project root:

```text
GEMINI_API_KEY=your_gemini_api_key_here
```

Replace the placeholder with your own API key. Never commit the `.env` file or expose your API key in source code, screenshots, or logs.

### 5. Run the Automated Tests

Run the complete test suite:

```powershell
python -m pytest
```

Run only the API tests:

```powershell
python -m pytest tests/test_shipment_api.py
```

Run only the AI evaluator tests:

```powershell
python -m pytest tests/test_ai_evaluator.py
```

Run the Gemini integration tests:

```powershell
python -m pytest tests/test_gemini_connection.py tests/test_gemini_shipment.py
```

**Note:** Gemini integration tests require a valid API key, internet access, and an available API model. Temporary provider errors or usage limits may cause these tests to fail.

### 6. Generate an HTML Test Report

```powershell
python -m pytest --html=reports/full_test_report.html --self-contained-html
```

Open the report on Windows:

```powershell
Invoke-Item reports/full_test_report.html
```

The report displays the results of the latest test run. Review the test summary and individual failures when troubleshooting.

## How the Framework Works

1. **Request Shipment Data:** The framework retrieves trusted shipment details from the shipment API.
2. **Generate an AI Response:** Google Gemini generates an answer to a shipment-related prompt.
3. **Evaluate the Response:** The evaluator checks the AI response against the trusted shipment status and destination.
4. **Validate Expected Behavior:** Automated tests check correct answers, incorrect statuses, conflicting information, and other negative scenarios.
5. **Generate Test Results:** Pytest executes the tests and can generate an HTML report containing the results.

This workflow demonstrates how API automation and AI response validation can be combined to test the accuracy and consistency of LLM-generated answers.

## AI Response Evaluation

The evaluator compares an AI-generated response with trusted shipment data.

Current validation checks include:

- Whether the expected shipment status appears in the response.
- Whether the expected destination appears in the response.
- Whether the expected status is negated.
- Whether another known shipment status conflicts with the expected status.

The evaluator returns a result containing:

- `passed`
- `status_correct`
- `destination_correct`

**Current limitation:** The evaluator uses keyword matching and basic negation checks. It is not a complete natural language understanding system, so valid responses with complex wording may be incorrectly rejected. More advanced semantic evaluation and context-aware validation are planned improvements.
